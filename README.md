# Anima Prompt Sorter 3.1 · AI Studio

Переработанный React + Vite проект из Google AI Studio. Фото → структурированный разбор сцены → компактный полный промпт, подробный промпт и теги за **один запрос Gemini**. Сохранены редактор категорий, веса тегов, сортировка текста, достраивание позы и кнопки копирования.


## Быстрый запуск в Google AI Studio

Это full-stack проект, как исходный архив: React + Vite → Express → `@google/genai`. Для AI Studio используйте обычный `npm run dev`, **не `build:pages`**. Сервер использует тот же SDK, `responseSchema` и заголовок `User-Agent: aistudio-build`, что и исходный проект. Специальный заголовок сохранён для совместимости; он не отменяет квоты или требования доступа.

1. Обновите файлы существующего проекта из архива или импортируйте репозиторий в AI Studio.
2. Выполните `npm install`, затем перезапустите приложение командой `npm run dev`.
3. В Secrets должен быть задан `GEMINI_API_KEY`. Если старый проект уже работал, сохраните его секрет. Вводить тот же ключ на странице повторно не нужно.
4. В интерфейсе появится сообщение «Ключ среды Google AI Studio / сервера найден». При пустом поле используется этот ключ; введённый вручную ключ имеет приоритет.
5. Выберите ту модель, которая работала в исходном проекте, или обновите список. Анализ фото, сортировка и дополнение текста используют выбранную модель через серверный SDK.

Сам ZIP не содержит ваш секрет. В новом проекте AI Studio наличие секрета нужно проверить. Если интерфейс пишет «Сервер недоступен», убедитесь, что запущен `npm run dev`, а не только `vite`: без Express маршруты `/api/*` не работают.

## Помощник для написания промпта

Введите в поле «Исходный промпт» свои слова, например: «девушка у окна, дождь за стеклом, смотрит на улицу». Под ним находится блок **Помочь написать промпт**:

- **Поправить формулировку** — исправить и связно оформить ваши слова без новых деталей.
- **Дополнить идею** — закончить описание и предложить совместимые детали, сохранив персонажей, одежду, действие и ограничения.
- В поле пожеланий можно написать: «добавь описание света, одежду не меняй».
- Нажмите **Помочь дописать мои слова**. Появятся редактируемый вариант на вашем языке, английский вариант и список добавлений. Исходный текст не заменяется автоматически.
- Нажмите **Вставить этот вариант в исходный промпт**, затем используйте существующие кнопки сортировки или анализа фото. Кнопка «Вернуть текст до дополнения» возвращает текст, который отправлялся помощнику.

Помощник работает с текстом, а не с прикреплённым фото. Для фото используется отдельная кнопка анализа. Ручные изменения русского варианта не переводятся в английский автоматически; английский текст можно редактировать отдельно.

## Как открыть через GitHub Pages

1. Распакуйте архив. Загрузите **содержимое папки проекта**, включая `.github`, в корень репозитория GitHub. Рядом должны находиться `package.json`, `src`, `.github`, `server.ts`. Сам ZIP загружать вместо исходников не нужно.
2. Основная ветка — `main`. Если другая, исправьте `branches` в `.github/workflows/pages.yml`.
3. В репозитории: **Settings → Pages → Build and deployment → Source → GitHub Actions**.
4. Откройте **Actions → Deploy GitHub Pages → Run workflow** (или отправьте новый commit в `main`). После завершения ссылка появится в Settings → Pages.
5. Откройте сайт, введите свой Gemini API key, нажмите **Обновить список из Gemini API**, выберите модель, загрузите PNG/JPEG/WebP до 8 МБ и нажмите анализ.

В GitHub Free Pages доступен для публичных репозиториев. Доступность для приватных зависит от плана GitHub. Публикуйте только исходники; `.env` и ключей в архиве нет.

**Pages — статический хостинг:** Express там не запускается. Workflow использует `npm run build:pages`: приложение отправляет запросы прямо из браузера в Google. Пользователь вводит свой ключ; общий ключ владельца не встраивается в JS или GitHub Actions Secrets. Ключ хранится в `sessionStorage` этой вкладки до её закрытия; его можно удалить кнопкой. Расширения браузера и скрипты того же origin могут читать браузерное хранилище. Для личного использования открывайте только доверенную копию приложения.

## Серверный режим: AI Studio, Codespaces или свой компьютер

Требуется Node.js 22+.

```sh
npm ci
cp .env.example .env
# Укажите GEMINI_API_KEY в .env (не коммитьте этот файл)
npm run dev
```

Откройте `http://localhost:3000`. В Windows можно скопировать `.env.example` в `.env` через проводник.

В Google AI Studio используйте server-side Secret `GEMINI_API_KEY`, затем `npm run dev`. AI Studio умеет импортировать репозиторий через Add files → Import from GitHub; также можно подтянуть изменения через Settings → GitHub. Настройки ключа проекта не переносятся внутри ZIP. Поле ключа в приложении имеет приоритет над серверным ключом; оставьте его пустым, чтобы использовать секрет среды.

В GitHub Codespaces: **Code → Codespaces → Create codespace**, дождитесь `npm ci`, выполните `npm run dev`, откройте порт 3000. Конфигурация `.devcontainer` включена. Оставляйте порт приватным, если используется ваш серверный ключ. Этот исходник не содержит авторизации или ограничения расходов для публичного сервиса с общим серверным ключом.

Продакшен-сервер:

```sh
npm run build
npm start
```

`PORT` задаётся окружением, по умолчанию 3000. Запуск собранного `dist/server.cjs` автоматически использует production-файлы. Статическая и серверная сборки используют одну папку `dist`; перед сменой режима выполните нужную сборку заново. Не запускайте сервер после `build:pages`: выполните `npm run build`.

Проверка статической сборки локально:

```sh
npm run build:pages
npm run preview:pages
```

Открывайте HTTP-ссылку из терминала; двойной клик по `index.html` не запускает Vite-приложение корректно.

## Модели и квоты

- Выпадающий список получает точные ID через `models.list`, включая пагинацию. Показаны Gemini-модели с `generateContent`; отдельные модели могут не поддерживать фото или JSON — API выдаст ошибку. Список не проверяет бесплатность или квоту.
- До обновления списка доступны алиасы Flash / Flash Lite / Pro и ручной ввод ID. Алиас может отсутствовать в вашем проекте. Неактуальный ID возвращает 404.
- Выбранная модель используется буквально: скрытого fallback и повторного расходования квоты нет. В результате отображается отправленный ID (для алиаса — сам алиас, не неизвестная нам внутренняя версия).
- 429 остаётся 429. Если Google прислал `RetryInfo`, показано время повторения. Это не гарантия, что дневная квота к тому времени восстановится. Лимиты привязаны к проекту; смена ключа того же проекта не сбрасывает их.
- 403 означает проблему доступа/ключа/региона; 404 — недоступную модель; 503 — перегрузку. Автоматических повторов нет.
- Работа в AI Studio не доказывает доступность той же модели/квоты с другим ключом. Сравните проект в Secrets, выбранную модель и квоты. В исходном архиве при любой ошибке происходил скрытый переход на `gemini-flash-latest`.

## Что изменено в анализе

В `src/lib/gemini.ts` находятся общие инструкции, JSON-схема, проверки и прямой транспорт для Pages. В `server/gemini-sdk.ts` — серверный транспорт через SDK, как в исходном проекте. Анализ отделяет наблюдаемые факты от пожеланий пользователя и неопределённости. Каждый персонаж получает свой ID, внешний вид, одежду, позу, руки и взгляд; отдельно описаны контакты, композиция, окружение и свет. Не требуются несуществующие низкие ракурсы, POV, улыбка или контакт с камерой. Имена и авторство не угадываются по стилю.

Короткий полный промпт — ориентир 80–140 английских слов для простой сцены. Подробный находится в раскрывающемся блоке разбора. Теги остаются редактируемыми; ручное редактирование тегов не переписывает уже полученные текстовые промпты — для этого повторно обработайте исправленный исходный текст. Генеративная модель может ошибаться; инструкции улучшают структуру, но не гарантируют точность распознавания.

Режим «Достроить позу» относится к текстовому запросу и может добавлять совместимые детали, перечисленные в «Пожелания и добавления». Фото анализируется по фактам; явные текстовые пожелания применяются к итоговым промптам. Кнопка качества добавляет только `masterpiece, best quality` к тегам, а не рейтинг `safe` или случайный score. Негативный промпт не подавляет все руки/конечности и нужный ракурс.

## Структура

- `src/App.tsx` — существующий редактор, загрузка фото, вывод и копирование.
- `src/components/ApiKeyInput.tsx` — ключ и выбор / обновление моделей.
- `server/gemini-sdk.ts` — серверный GoogleGenAI с конфигурацией исходного AI Studio проекта.
- `src/components/PromptAssistant.tsx` — помощь в написании текста, предпросмотр и принятие варианта.
- `src/components/AnalysisPanel.tsx` — разбор сцены и подробный промпт.
- `src/lib/gemini.ts` — единая логика Google API, схема, валидация и ошибки.
- `src/lib/api.ts` — выбор прямого или серверного транспорта.
- `server.ts` — Express API и раздача production-сборки.
- `.github/workflows/pages.yml` — тесты, сборка и публикация Pages.
- `.devcontainer/devcontainer.json` — Codespaces.
- `tests/gemini.test.ts` — проверки с подставными ответами Google, без реальных ключей и расходов.

```sh
npm run lint
npm test
npm run build
npm run build:pages
```

Автотесты используют подставные ответы; дополнительные SDK-тесты проверяют реальную сериализацию запроса, исходный заголовок AI Studio, режимы помощника и преобразование ошибок. Они проверяют передачу выбранной модели/фото, 429 без скрытых повторов, валидацию входа, неполный ответ и пагинацию моделей. Реальный анализ с вашим текущим ключом нужно проверить после запуска: ключ не извлекается из AI Studio и не включён в архив.

Официальные справки: [Gemini models.list](https://ai.google.dev/api/models), [AI Studio Build и Secrets](https://ai.google.dev/gemini-api/docs/aistudio-build-mode), [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages), [Pages workflows](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages), [Gemini quotas](https://ai.google.dev/gemini-api/docs/rate-limits).
